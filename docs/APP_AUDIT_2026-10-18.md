## Scope and method

The review covered the main HTML application and navigation, role-aware views, the School Command Centre, creator Master Control Centre, notice authoring/reading flows, the central sound engine and its settings UI, the email automation Edge Function, Supabase RLS policies/advisors/migration history, and the GitHub Pages deployment workflow. Static JavaScript parse checks passed for the main inline scripts and the academic, assessment/notification, Command Centre, theme and sound modules. Database metadata and policy catalogues were queried directly. A static/source review cannot prove the authenticated browser experience works for every user role; separate real-account acceptance tests remain necessary.

## Changes made during this review

1. **Appearance Studio:** added eight polished themes—Rose Gold, Pearl Ivory, Ocean Blue, Sage Garden, Lavender Mist, Teal Glass, Sandstone and Midnight Luxe—plus text-size and reduced-motion preferences. Preferences are account-specific and sync through a new `user_theme_preferences` table protected by user-ID RLS policies. The default returns to Rose Gold.
2. **Settings integration:** added the Appearance Studio to each signed-in user's settings, while keeping sound preferences separate. The settings navigation now says “Appearance & Sound”.
3. **Notice entry points:** added “Create & send notice” / “Open notice board” actions to the School Command Centre notice widget and a notice shortcut to the platform Creator's Master Control Centre.
4. **Recipient navigation:** exposed School Notices in student and parent/guardian navigation.
5. **Notice audience handling:** added school-owner and parent/guardian audiences to the composer. Student and teacher notice reads now filter to active notices targeted to that role and to the publish/expiry window; the live RLS read policy also enforces school scope, role targeting, active status and time window.
6. **Deployment assets and automated checks:** included `theme-system.js` and `theme-system.css` in the GitHub Pages asset allow-list. Added Playwright checks for the login/registration shell, all eight themes, text size/reduced motion, and the Sound & Feel panel controls.
7. **Documentation:** refreshed the README to describe current features and to avoid labelling the project as production-accepted before the missing tests are complete.

## Important behaviour to understand

- Pressing **Send notice** publishes the notice to the selected recipients' in-app notice board. It does not automatically email the recipients. Email delivery is a separate, provider-configured workflow.
- Themes are personal account preferences. One student's theme choice must not change a classmate's or school's data/access permissions.
- The existing sound engine already has a central manager, mapped sound categories, volume/mute controls and preference persistence. It was retained rather than replaced with an uncoordinated second audio implementation.
- The school Command Centre still contains explicitly labelled planned/not-configured areas. These should not be presented as completed fee collection or parent-query functionality.
